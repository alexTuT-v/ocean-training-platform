# Training Platform 前端与页面设计

日期：2026-11-23  
状态：已确认  
范围：面试评估所需的 React 前端；与已确认的后端设计配套

## 1. 目标与边界

为租户管理员提供清楚、可验证的证书管理界面：选择演示管理员、查看课程完成情况、批量颁发、查询和撤销证书、按当前筛选与排序导出 CSV。界面应明确呈现加载、空结果、错误、处理中和逐学员结果；避免重复点击引发额外写入。前端只展示后端授权的租户数据，不自行决定租户范围。

评估文档要求 React 或 Vue 3、一个命令启动完整应用，且核心行为优先于视觉打磨。这里选 React + TypeScript + Vite，使用浏览器原生 `fetch`；当前规模下以少量组件状态和 URL 查询参数管理页面状态，不引入全局状态库。后端构建时提供静态前端资源。具体版本在实施计划中锁定。

不做登录页、生产权限管理、通知、课程编辑、学员编辑、单次颁发和额外看板。演示管理员切换是评估要求中的身份模拟，不能当作真实登录。

## 2. 考虑过的页面结构

| 方案 | 页面安排 | 取舍 |
| --- | --- | --- |
| A：证书页 + 课程页（已选） | 证书页处理查询、详情、撤销和导出；课程页处理完成情况与批量颁发 | 两条主要任务清楚分开；详情适合侧栏，批量结果留在原页 |
| B：单页标签工作台 | 所有操作在一个页面通过标签切换 | 导航少，但证书详情、课程状态与批量结果容易相互挤占空间 |

用户选择 A。两页共用顶部栏和左侧导航；管理员选择器位于顶部右侧，显示 `Alice · East` 或 `Bob · West`。没有独立的租户选择器：前端仅传 `X-Actor-Email`，由后端查出租户。视觉采用清晰的表格、适度留白和可辨识的状态标记；桌面浏览器优先，小屏允许表格横向滚动，不隐藏关键操作。

## 3. 页面与导航

路由为 `/certificates` 和 `/courses`；访问根路径转到证书页。浏览器刷新与前进/后退保持当前页面；证书页的 `search`、`sort`、`direction`、`page` 保存在 URL 查询参数中，导出读取同一组参数（不含 `page`）。切换管理员时清空旧租户数据及页面状态，导航到证书页并恢复默认筛选排序；任何旧请求的晚到响应不得覆盖新身份数据。

### 3.1 全局顶部栏

左侧显示产品名，右侧显示当前管理员和租户名。点击右侧菜单可在预置的 Alice (`alice@east.test`) / Bob (`bob@west.test`) 之间选择；这些演示选项来自已知种子数据，后端 `GET /api/me` 再确认实际管理员、租户及时区。身份未确认时显示加载状态，失败时显示错误与重试，不展示上一位管理员的数据。进行中的写请求禁用切换，直到请求得到成功或失败结果；请求失败时保留原操作的重试信息。

前端从管理员上下文构造 `X-Actor-Email`。业务数据不以单独 tenant ID 请求。使用请求代次标识及 `AbortController` 处理切换时的旧请求；即使取消未成功，也忽略旧代次结果。客户端不缓存跨管理员业务响应。

### 3.2 证书页

页头：标题、当前租户及时区、`导出 CSV` 按钮。筛选行：按学员姓名或序列号的搜索框、排序字段（本地签发日期、学员、课程、序列号）及升降序控制。搜索变化时重置到第一页；搜索可短暂防抖，排序和翻页立即请求后端。页面使用后端分页，不在浏览器加载全部证书。

表格列：序列号、学员、课程、租户本地签发日期、状态。`ACTIVE` 与 `REVOKED` 都显示；行可打开右侧详情栏。分页显示当前页和总数。状态包括首次加载骨架、筛选中加载、无证书、搜索无结果、请求错误及重试。刷新或一次写操作完成后重新读取当前页，获取最新已提交状态。

详情侧栏显示序列号、学员、课程、带时区标识的本地签发日期时间、状态。有效证书显示“撤销证书”按钮；点击后弹确认框，明确序列号和不可恢复的状态变更。已撤销证书保留详情但不提供再次撤销的主按钮。撤销成功后更新详情并重新请求列表；若来自新幂等键的重复撤销返回“已撤销”，显示中性提示，不冒充新发生的撤销。

### 3.3 课程完成页

页头：标题、当前租户、课程选择框。选择课程后请求其选课情况，显示已完成、未完成、已有有效证书等数量，以及学员表格（学员、完成状态、有效证书状态/资格说明）。课程切换时清空上一课程数据，提供加载、空课程、空选课和错误状态。

“批量颁发”始终以当前所选课程为目标，按钮旁说明“仅为已完成且当前无有效证书的学员颁发”。点击先显示确认框，再发送写请求；发送期间禁用该按钮并显示处理中。响应后在课程页展示操作状态、颁发/跳过/失败数量和逐学员结果及原因；`issued` 项可通过证书 ID 打开对应详情或导航证书页。再次明确发起批量操作会生成新幂等键，已有效获证者被后端跳过；已撤销者可以再次获证。

## 4. 写请求与幂等键的前端规则

当前写 API 只有 `POST /api/courses/{id}/bulk-issue` 和 `POST /api/certificates/{id}/revoke`，都必须带 `Idempotency-Key`。管理员确认一次操作意图时生成随机 UUID；请求超时、网络失败或需重试时保留并复用同一键、同一管理员、同一 URL 和请求体。用户明确启动一项新操作时才生成新键。对同一个未决操作，前端只允许一个在途请求；服务端仍独立保证幂等。

为应对响应丢失，前端在 `sessionStorage` 保存未决操作的管理员、方法、路径、规范化请求体、键及创建时间；完成并收到确定结果后清理。页面刷新后若存在未决操作，在原管理员上下文提示“继续查询结果”，使用原键重试；不自动生成新键。`409` 显示“此操作键已用于另一请求”，不偷偷换键重发；用户可显式放弃当前操作并重新开始。未知结果时不得直接提示“操作失败且没有生效”。切换管理员不会把一位管理员的未决操作重试为另一位管理员。

写成功后触发相关读请求重新获取当前状态。撤销的相同键重试显示首次响应；新键重复撤销显示当前已撤销但没有新增审计。批量返回的整体 `COMPLETED` 只表示处理结束，界面仍要分别突出每名学员的 `issued`、`skipped`、`failed`。

## 5. 读请求与 CSV 导出

所有 GET 请求不带幂等键，不产生业务副作用。每次用户操作或写入完成后的新请求都重新访问后端，不复用旧响应；`fetch` 使用不缓存选项。若请求期间另一个写入提交，该次查询可返回其开始时的已提交视图，下一次 GET 应看到新状态。前端仅展示服务端返回的租户本地日期/时间，不按浏览器所在时区重新计算。

导出按钮读取当前证书页 URL 中的 `search`、`sort`、`direction`，发起无分页的 GET；下载期间标示“正在导出”和发起时的管理员/租户。导出采用异步 `fetch` 并生成浏览器下载，不能锁住列表查询、排序和分页；即使用户随后切换管理员，导出的请求仍绑定发起时捕获的管理员，下载文件名包含对应租户。若导出失败，保留页面筛选条件并允许重试。10 万行导出性能由后端 A6 验证；前端避免把 CSV 解析为页面表格。

## 6. 与后端的接口契约

前端使用后端设计中的接口，不新增写端点。具体 JSON 名称实施时需与后端固定为同一契约；页面至少依赖以下字段：

| 接口 | 页面所需数据 |
| --- | --- |
| `GET /api/me` | 管理员邮箱、租户名称、租户时区 |
| `GET /api/courses` | 当前租户课程 ID、标题 |
| `GET /api/courses/{id}/enrollments` | 学员 ID/姓名、完成状态、当前有效证书状态 |
| `GET /api/certificates` | 证书 ID、序列号、学员、课程、本地签发日期、状态、分页总数 |
| `GET /api/certificates/{id}` | 上述详情及本地签发日期时间 |
| `POST /api/courses/{id}/bulk-issue` | 操作 ID、完成状态、颁发/跳过/失败数量、逐学员结果与原因 |
| `POST /api/certificates/{id}/revoke` | 操作 ID、证书 ID、最终状态及本次是否发生状态变化 |
| `GET /api/certificates/export` | CSV 响应；沿用当前搜索和排序，不分页 |

前端统一处理 `401`（未知演示管理员）、`404`（对象不存在或不属于当前租户）、`409`（幂等键冲突）、`422`（参数错误）和临时服务错误。错误消息不展示敏感响应原文；保留重试所需的上下文。不要在 UI 中承诺“撤销已写审计”之类无法从接口直接证明的事实。

## 7. 可访问性与验证

搜索框、选择框、按钮与表头排序均有文字标签；加载和操作完成信息通过可读状态区域呈现；确认框与侧栏支持键盘操作及焦点返回。颜色用于辅助区分状态，同时保留“有效/已撤销”“已颁发/跳过/失败”的文字。

前端验收覆盖：Alice/Bob 切换后不残留另一租户数据；搜索、排序、分页与导出参数一致；空和错误状态可恢复；撤销先确认且重复请求不误导；批量操作禁用重复点击并展示逐学员原因；超时重试使用原幂等键；读请求在写入提交后重新获取新状态；10 万行导出期间列表仍可操作。A1–A7 的最终正确性仍以 API、数据库和 UI 联合验证。

## 8. 已确认的选择与待实施工作

用户确认页面结构 A（证书页 + 课程页）、顶部右侧管理员切换、证书详情侧栏、课程页内的批量结果位置。React + TypeScript + Vite、URL 查询参数、原生 `fetch`、未决写操作的 `sessionStorage` 保存及视觉细节为设计者选择；不把这些描述为用户指定。

实施前需把第 6 节的 JSON 字段形状固定到前后端共用契约，编排一条命令完成前端构建、演示数据初始化及后端启动。本文档已由用户批准，前端实施计划已单独编写。
